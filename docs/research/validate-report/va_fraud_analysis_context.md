# 1. Business Context

## 1.1 Product Purpose

Virtual Account (VA) in TTT is designed primarily to:

- Allow **personal users to deposit large value in one transaction**
- Support **value storage and later withdrawal**
- Not designed for **high-frequency daily transaction execution**

Typical user behavior:

- Most users deposit **1–3 VA transactions per day**
- VA should **not function as a high-frequency transfer rail**

---

## 1.2 Cash-out Policy (Important for Fraud Incentive)

Two withdrawal mechanisms create arbitrage opportunities:

### Personal Users
- Cashout P2P: **Free up to 100M VND / month**

### Merchant Users
- Cashout via Napas: **Free and unlimited**

Potential exploit strategy:

1. Deposit many small VA transactions
2. Aggregate balance
3. Withdraw through free channels

This creates an incentive for **transaction splitting and repeated deposit cycles**.

# 3. Fraud Explosion Period (10/2025 – 01/2026)

Observed transaction growth:

| Month | VA Transactions |
|------|------|
| Typical 2025 months | ~500,000 |
| Oct 2025 | ~1,000,000 |
| Nov 2025 | ~3,000,000 |
| Dec 2025 | ~4,000,000 |
| Jan 2026 | ~5,100,000 |

Investigation revealed:

- ~5% of users performed **extreme high-frequency deposits**
- These users generated **~85% of all VA transactions**

# 5. Statistical Outlier Context

Typical outlier detection principle:

Outlier threshold:

Mean + 1.5 × standard deviation of normal user behavior

Estimated threshold:

≈ **10.8 transactions/day**

Implication:

If behavior were natural:

- Only **~1% of users** should exceed this threshold.

Observed reality:

- **~5% users exceed this threshold**

Therefore:

- At least **4% users represent abnormal behavior cluster**.

---

# 6. Fraud Pattern Characteristics

Fraud users exhibit:

- Extremely high daily transaction counts
- Transaction splitting patterns
- Repetitive deposit-withdraw loops

Observed ranges:

| Behavior Tier | Transactions/day |
|------|------|
| Normal | 1–3 |
| Heavy but plausible | 4–9 |
| Suspicious threshold | 10+ |
| Extreme fraud cluster | 72–250 |

Distribution shows **step-change discontinuity** rather than gradual decay.

This suggests:

- Coordinated behavior
- Scripted / automated patterns
- Exploitation of withdrawal policies

---

# 7. Risk Decision: Introduce Transaction Cap

Policy introduced in **Feb 2026**:

**Maximum VA deposits per user per day = 10 transactions**

---

## 7.1 Rationale for Cap = 10

Key supporting facts:

1. **95% users naturally operate ≤10 transactions/day**
2. Extreme fraud cluster starts **above 10**
3. Clear statistical breakpoint between normal and abnormal behavior

Trade-off analysis:

| Scenario | Impact |
|------|------|
| If cap is wrong | Affects at most ~1% legitimate heavy users |
| If cap not implemented | Allows ≥4% fraud users to generate millions of transactions |

Expected benefits:

- Remove ~80% of extreme fraud activity
- Protect normal users
- Improve operational control

# 8. Post-Mitigation Observations (Feb 2026)

1. Fraud accounts locked

3. New VA entry point launched on **MoMo Home UI**

# 9. Key Analytical Questions

The analysis must answer three major questions.

---

# A. Detect Abnormal Behavior Patterns

Goal:

Statistically demonstrate that fraud cluster behavior is not natural user behavior.

Required analyses:

- Distribution analysis
- Heavy-tail detection
- Outlier modeling
- Behavioral segmentation
- Fraud cluster detection

Potential methods:

- Tukey IQR outlier rule
- Pareto distribution analysis
- Lorenz curve
- Gini coefficient
- Power-law fitting
- Mixture distribution modeling

Key proof target:

Show that **high-frequency deposit behavior forms a separate regime**.

---

# B. Validate the 10 Transaction Cap Decision

Goal:

Statistically justify the decision to limit VA deposits.

Key validation points:

1. Majority user needs ≤10 deposits/day
2. Extreme fraud cluster begins beyond this threshold
3. Cap protects most users while removing fraud tail

Evidence required:

- Distribution percentile analysis
- Outlier threshold estimation
- Fraud cluster concentration
- Transaction contribution analysis

Desired outcome:

Demonstrate that **cap = 10 is statistically defensible**.

---

# C. Evaluate Real Growth After Fraud Removal

Goal:

Determine whether VA growth in Feb 2026 is genuine.

Potential confounding factors:

- Fraud traffic in late 2025
- Fraud users inflating transaction volume

Proposed approach:

Construct a **clean population**:

Users whose behavior always remained within:

≤ P94 (≤9 VA transactions/day)

Then compare:

| Period | Metric |
|------|------|
| Baseline | 6 months before Feb 2026 |
| Test period | Feb 2026 – Mar 2026 |

Perform statistical tests on:

- Daily transaction volume
- Unique VA users
- GMV

Suggested tests:

- Two-sample t-test
- Mann–Whitney U test
- Bootstrap difference-of-means
- Time series intervention analysis

Objective:

Validate whether the **new Home UI deposit entry point caused real growth**.
